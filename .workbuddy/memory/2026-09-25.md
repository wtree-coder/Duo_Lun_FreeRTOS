## 云台 yaw 反馈源讨论：IMU vs 电机编码器（只读，未改码）

用户提议把 `Gimbal_Data_Update` / `Gimbal_PID_Calc` 的 yaw 反馈源
从 `imu_euler_data.yaw` 换成 `gimbal.motor_6020.now_angle`。**结论：不建议，会丢掉自稳。**

### 参考系关系（核心）
yaw 电机固定在底盘上，IMU 装在云台上：
```
yaw_imu     = yaw_chassis + theta_motor      (角度)
gz (IMU)    = omega_chassis + omega_motor    (角速度)
```
- `imu.yaw`：云台**相对世界系**（惯性系），归一化 [-π, π]（atan2f 折叠）
- `motor.now_angle`：云台**相对底盘**，多圈连续（total_round*8192 + rx_encoder）
- 两者用途不同，**当前代码用对了**：自稳用 IMU，底盘跟随用电机角（`delta_angle`）

### 结论
1. **用 IMU 做 yaw 外环反馈是正确的** —— 这是"自稳"（底盘转动时云台在世界系不动）。
   换成电机角后控的是"云台相对底盘角"，底盘一转云台就跟着转 → **自稳失效，枪口随车体摆**。
   改动还会波及 `Gimbal_Homing` 里 `target_yaw = imu_euler_data.yaw`（须改为 0，因 angle_offset 已标定）。
2. **真 bug 在内环参考系不一致**（不是反馈源选错）：
   外环 `PID_angle(now=imu.yaw, target=target_yaw)` 的输出是**世界系**角速度，
   却被直接当成内环 `PID_omega(now=motor.now_rad_s)` 的目标 —— 内环是**相对底盘**的电机转速。
   二者差一个 `omega_chassis`。底盘静止时无影响，底盘转动时云台被拖着晃，只能靠积分硬扛，动态响应差。
   **正解**：内环目标 = 外环输出 − ω_chassis，且 `omega_chassis = gz − omega_motor` **可自算**，
   不依赖 A→C 通信（当前 CAN 是单向 C→A，C 板拿不到底盘数据）。
3. **IMU yaw 漂移是真实问题**，但解法是加磁力计 / 陀螺零偏标定，不是换反馈源。
4. 若产品形态本就不需要自稳（底盘极稳、或只要随动），用户方案更简单可靠 —— 但那就不是自稳云台了。

### 附带确认
- `imu_euler_data.yaw`：**归一化** [-π, π]，跨 ±π 跳变（atan2f）。
- `Motor_t.now_angle`：**连续增长**多圈。两者性质相反，勿混用。
- `To_2PI()` 命名误导：实际归一化到 [-π, π]（不是 [0, 2π]），建议改名 `Wrap_PI`。
- 当前 `target_yaw = imu.yaw + To_2PI(target_yaw - imu.yaw)` 这行**必需，不能删**（用户曾质疑是否多余）。
- **它防的不是"进入 MOVE 瞬间的突变"**（DISABLE 每帧 `target_yaw = imu.yaw` 已解决该问题），
  而是**运行过程中 `imu.yaw` 归一化跳变**：
  `imu.yaw` 恒定锁在 [-π, π]，而 `target_yaw` 是每帧 `+= 0.005` 累加的连续量。
  一旦云台累计转过 180°，`imu.yaw` 从 +3.14 跳到 -3.14，而 `target_yaw` 还停在 +3.14，
  `error = 2π` → PID 疯转一整圈。**必然发生**（满杆 5 rad/s 时约 0.63 秒即触发）。
- 本质：`imu.yaw` 被 atan2f 锁死在同一个圈内，`target_yaw` 必须被拉回同一个圈，减法才有意义。
- 副作用：该行使云台**最多只能转半圈**（目标推过 ±π 会翻到反方向）。若要连续转多圈，
  需先做"IMU yaw 连续化"（检测 ±π 跳变后 ±2π 累加），再删掉这行。
- 次要作用：防止 `target_yaw` 无限累加导致 float 精度退化（V≈1e4 时 ULP≈0.001，接近 0.005 步进）。

## 纠正：GM6020 CAN 协议（上面两条判断都错，已查官方手册）

- 控制帧 ID：**0x1FF = GM6020 电压控制（ID1~4）的正确帧**；0x1FE 是「电流控制」（需升固件+开电流环）才用。当前 0x1FF 正确，不改。
- 电压范围：官方 v1.2(2020.05) = **-30000~30000**（社区共识）；v1.4(2023.10) 的 ±25000 是另一版本/电流模式数值。`MOTOR_6020_OUT_LIMIT=30000` 正确，不改。
- 教训：协议/数值类结论必须先查官方手册，勿凭记忆断言。
