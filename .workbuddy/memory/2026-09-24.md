## Board_A 工程通读（只读，未改码）

用户要求：先通读 Board_A，之后由他提问；**任何代码改动都要先讨论再动手**。

### 工程定位
- STM32F427（Keil MDK-ARM + STM32CubeMX 生成），HSE 经 PLL 到 180MHz，FreeRTOS CMSIS-RTOS v2，`configTICK_RATE_HZ=1000`。
- A 板 = **舵轮底盘**主控：4×3508 驱动轮 + 4×6020 转向轮。C 板 = 云台主控。
- 目录分层：Core(CubeMX 生成) / BSP(drv_can、motor、pid、vofa) / Mid(chassis_config、communication、callback、vofa_config) / Task。

### 外设与引脚
- CAN1: PD0/PD1，3508 驱动轮；CAN2: PB12/PB13，6020 转向。均 Prescaler=3（APB1 45MHz → 1Mbps）。
- USART6: PG14/PG9，115200，接 VOFA+（DMA 发送）；USART3: PD8/PD9，115200。
- CAN 中断优先级 5（= configMAX_SYSCALL，边界值，可调用 FromISR API）。

### 任务
- `Task_Chassis`（osPriorityHigh，栈 512×4）：1ms 调 `Chassis_PID_Calc_1ms_Callback()`，跑逆解 + PID + 发 CAN。
- `Task_Data_Get`（osPriorityNormal，栈 256×4）：做 CAN_Init/滤波器配置/Vofa_Init，1ms 调掉线检查 + VOFA 发送（内部 20 分频 → 20ms）。

### CAN 协议
- 收：0x300（C→A，7 字节：vx/vy/云台相对角量化×1000/拨杆档位）；0x201~0x204（3508 反馈，CAN1）；0x205~0x208（6020 反馈，CAN2）。
- 发：0x200 → 3508 电流（CAN1）；0x1FF → 6020 电压（CAN2）。
- 滤波器：CAN1 filter0 掩码 0x7FF 只收 0x300；CAN1 filter1 掩码 0x7F0 收 0x200~0x20F；CAN2 filter14 掩码 0x7F0 收 0x200~0x20F；SlaveStartFilterBank=14。

### 控制链路
`Chassis_Follow_Calc`(wz = delta_angle × 3.0，限 ±3) → `Chassis_Swerve_IK`(每轮 vix/viy → speed/steer，含 ±90° 最短路径翻转 + 低速死区保持转角) → 6020 角度环→速度环串级，3508 单速度环 → CAN 下发。

### 通读时发现的可疑点（待用户确认后再动）
1. `Chassis_Init` 里 **12 个 PID 的 Kp/Ki/Kd 全为 0**，且 6020 角度环 `integralLimits` 用了 `MOTOR_6020_MAX_RPM*RPM_TO_RADPS`（拿转速限幅当积分限幅，量纲不对）。
2. `angle_offset`（6020 零点标定）从未赋值，也无标定流程。
3. `Motor_Check()` 定义但**无人调用**；`Motor_t.is_ok` 恒不更新。掉线只有 chassis 级 `receive_check_count>500` 判定。
4. `Chassis_XiaoTuoLuo` 模式走 else 分支全停，未实现。
5. `drv_can.c` 中 `CAN1_0x1ff_Tx_Data` / `CAN1_0x200_Tx_Data` 定义未使用；6020 实际发在 CAN2 上，命名有误导。
6. 两个任务都用 `tick++; osDelayUntil(tick)`，被抢占错过周期后会连续补跑。
7. `callback.c` 中断里 `chassis.is_ok = 1` 无条件置位，任一通过滤波的帧（含 0x300）都会让底盘认为电机在线。
8. VOFA 只发了 vy + 4 路 6020 total_encoder，缺转角误差/轮速/out 等关键量。

## Board_C 工程通读（只读，未改码）

### 硬件
- **STM32F407IGHx**（注意与 A 板 F427 不同），HSE→PLL **168MHz**（A 板 180MHz），同为 FreeRTOS + CMSIS-RTOS v2。
- 角色：**云台 + 遥控 + IMU** 主控，向 A 板单向发指令。

### 外设
- CAN1: PD0/PD1（**BS1=10TQ, BS2=3TQ**, Prescaler=3 → 42M/(3×14)=**1Mbps**；A 板 45M/(3×15)=1Mbps，**两边波特率一致 ✓**）
- CAN2: PB5/PB6，CubeMX 初始化了但**从未 Start / 无滤波器**，闲置。
- USART3: PC11/PC10，**100000 波特**接 DR16（DMA + IDLE 中断，18 字节帧）
- USART1: PB7/PA9，115200 接 VOFA+；USART6: PG14/PG9，115200（预留）
- SPI1: PB3/PB4/PA7，**Prescaler=256 → 328kHz**，接 BMI088（CS: PA4 加速度 / PB0 陀螺）
- TIM10 CH1 (PF6): IMU 加热电阻 PWM，ARR=4999；TIM3/4/5 配成 PWM 但未见使用；I2C3 未见使用

### 四个任务
| 任务 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|
| Gimbal | **High1（最高）** | 512×4 | 1ms | 掉线检查/Homing/模式/PID/CAN 发 |
| IMU | High | 256×4 | 1ms | 读 BMI088 + 温控 + Mahony 解算 |
| Communicate | High | 512×4 | 1ms | 发 0x300 给 A 板 |
| Data_Get | Normal | 256×4 | 1ms | DR16 掉线检查 + VOFA 20ms |

### 云台控制链路
- `Gimbal_Task_1ms_Callback`：`Motor_Check` → `is_ok` → 掉线则回 HOMING；Homing 要求 `|now_rad_s|<0.5` 稳定 300ms 后标定 `angle_offset = now_angle`、`target_yaw = imu.yaw`、转 DISABLE。
- MOVE 时：`target_yaw += 摇杆X × 0.005`（1ms 步进），外环 IMU yaw → 目标角速度，内环 6020 速度环 → `out`，`0x1FF` 下发。
- `delta_angle = To_2PI(motor.now_angle - angle_offset)`（用**电机编码器**而非 IMU yaw，正确）→ 随 0x300 发给 A 板做跟随。

### 通读发现的可疑点（待确认后再动）
1. **yaw 必漂移**：只用 BMI088（无磁力计，I2C3 闲置）+ `MahonyAHRSupdateIMU`，`twoKi=0`，且**无 gz 零偏标定**。yaw 是纯陀螺积分。
2. **外环缺底盘角速度前馈**：`target_rad_s` 直接来自角度环，底盘转动会带动云台 yaw，自稳会被底盘运动耦合。
3. **GIMBAL_SHOOT 是死代码**：`Gimbal_Mode_Choose` 只能产出 MOVE / DISABLE。
4. **`CAN_Init(&hcan1)` 被调用两次**（`Gimbal_Init` 和 `Task_Communicate`）；CAN 滤波器只在 Gimbal_Init 配（只收 0x205）。
5. **SPI 偏慢**：Prescaler=256 → 328kHz，一轮要传 ~20 字节 ≈ 600μs（占 1ms 预算 60%），余量约 30~40%。
   **查证（9-24）**：`SPI_BAUDRATEPRESCALER_256` 写死在 `Board_C.ioc:407`（`SPI1.CalculateBaudRate=328.125 KBits/s`），属**本工程 CubeMX 配置**，
   **不是 imu.c 封装的一部分**——imu.c 从头到尾只调用 `HAL_SPI_Transmit/Receive`，对波特率完全无感，其 @note 也只要求 PA4/PB0 推挽 + TIM10 PWM。
   BMI088 手册 SPI 上限 10MHz，328kHz 离上限差 30 倍，非硬件限制。
   **判断修正**：只要 `IMU_Update()` 稳定 < 1ms（实测余量够），`vTaskDelayUntil` 保证 1ms 周期，`sampleFreq=1000` 写死是**成立的**，系统能正常工作。
   真实风险是余量薄导致抖动（噪声，非系统性偏差）。**结论：先测真实 dt 再决定是否提速，不要凭估算改。**
6. `Task_IMU.c:33` `xLastWakeTime` 写在循环内（A 板用的是 `tick++` 写法，两边不一致）。
   **更正（9-24 复核）**：该写法只要 `IMU_Update()` 耗时 < 1ms，周期仍是准确的 1ms（因为基准在 Update 之前取）。
   真实缺陷是"超时后不追赶"——一旦某次 Update 超过 1ms，周期被拉长且后续不补偿。真正要治的是两点：SPI 太慢（余量只剩 200~300μs）+ Mahony `sampleFreq` 写死 1000。
7. `Motor_Check` 掉线用 `memset` 清整个 `Motor_t`，**会把标定好的 angle_offset 和 total_round 一起清零**（C 板 50 次即 50ms 触发）。
8. `IMU_ReadTemperature` 写死全局 `imu_raw_data` 而非传入的 `raw` 指针。
9. VOFA 通道重复：`temp[0]` 与 `temp[2]` 都是 `total_encoder`，缺 yaw / target_yaw / out。
10. `Mid/chassis_config.c` 是空壳（只有一行 include），`Chassis_t` 在 C 板从未实例化。
11. 速度量程不一致：A 板 `V_MAX=2.0f`（注释却写 3 m/s），C 板 `MAX_V=3000.0f` 只是量化刻度，实际满量程 2 m/s。
12. 两板 `drv_can.c` 逻辑等价（仅参数名 Config_Data / Object_Para 不同）；`motor.c`、`pid.c` **完全相同**；`vofa.c` 仅 C 板开了 DMA 接收。
